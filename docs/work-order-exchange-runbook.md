# 作业单文件交换：常见情况处置（值班一页）

面向值班/运维。格式细节见 [work-order-csv-exchange.md](work-order-csv-exchange.md)。原则：**导入是行级独立事务，成功行已落库；任何重导都必须换新请求号，系统靠单号判重保证不产生重复单。**

## 导入部分失败（最常见）

现象：返回 `success=true` 但 `failedCount > 0`。
处置：
1. 从 `data.rows` 里筛 `status=FAILED` 的行，按 `lineNo`（表头为第 1 行）回源文件定位，对照 `message` 修正。
2. 把失败行单独存成一个新 CSV（**保留表头行**），用**新 requestNo** 再导。
3. 不要原文件整体重导——成功行会全部判 SKIPPED，虽无害但掩盖真实结果。

## 按失败原因分类处置

| 报错 | 含义与处置 |
| --- | --- |
| 农机不存在： xxx | machineCode 未建档或拼错。先 `GET /api/machines` 核对编码，必要时先给农机建档再重导该行 |
| 农机已停用 | 该农机 DISABLED，不能建新单。确认是否应启用；确需建档先恢复农机状态 |
| 作业单号已存在且内容冲突 | 单号已被占用且字段不一致。`GET /api/work-orders?orderNo=xxx` 查现有单，与对方确认以哪边为准；以文件为准则线下改单号或先红冲原单，以库为准则该行从文件删除 |
| orderNo/machineCode/operationType 不能为空 | 行内必填列空缺，常见于 Excel 误删列。补值后重导该行 |
| 长度超过 N 字符 | 列超长（orderNo 40 / machineCode 40 / operationType 40 / plotName 80 / remark 255），截短或拆分 |
| 列数不符 | 多了或少了逗号，常见于手工改行。对照模板修正；字段里要含逗号必须整体加双引号 |

## 整批被拒（success=false）

| 报错 | 处置 |
| --- | --- |
| 请求号已处理，请勿重复提交 | 该 requestNo 已用过（含上次失败的批次）。**换新请求号**重提；这不是数据问题 |
| 表头与模板不一致 | 重新 `GET /api/work-orders/import-template` 下载模板，把数据贴进模板再导。注意表头区分大小写、不能有空格/多余列 |
| CSV 解析失败：第 N 行… | 引号未闭合或引号后有多余字符。按行号定位，检查该行引号是否成对、字段内引号是否双写 |
| 文件为空 / 没有数据行 | 文件内容为空或只有表头；确认上传的是填好数据的文件，不是空模板 |
| 单次导入最多 5000 行 | 拆成多个文件分批导，每批一个请求号 |

## 文件内容问题

- **Excel 打开乱码**：用导出文件（自带 BOM）直接双击打开；不要把无 BOM 的文件另存为"ANSI"。
- **Excel 编辑后导入报格式错**：Excel 可能改动引号/行尾。另存时选"CSV UTF-8（逗号分隔）"；仍报错就用文本编辑器对照模板检查表头与引号。
- **字段里的逗号/引号/换行**：必须整体双引号包裹、内部引号双写（模板第二行有示范）。单元格内换行（Alt+Enter）是允许的，导入按起始行号报告。
- **重复导入同一文件**：换一个新 requestNo 即可，已存在的行全部 SKIPPED、不产生重复单；想确认是否真的幂等，看返回里 `createdCount` 应为 0。
- **导出超 10000 行被拒**：用 `orderNo` / `status` / `machineCode` 参数分批导出。

## 升级路径

无法按上表处置（如怀疑丢数据、需批量回滚某次导入）：保留导入文件与返回结果（含批次 requestNo），联系系统负责人。台账可按 `t_request_record` 中 `biz_type=WORK_ORDER_IMPORT` 及行级请求号 `批次requestNo#L行号` 追溯每笔导入来源。
